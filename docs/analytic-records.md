Analytic requests and results are immutable observations in the session SQLite database. They do not create fills, cash postings, economic ledger events, or state-version increments.

`prepare_analysis` freezes the exact job, managed campaign inputs, bounded admitted universe and its exclusions, account limits, proposal, selected draft, and complete market snapshot before returning a dispatchable request. The record carries the original session, branch, state version, selection, snapshot identity, pack identity, and rule identity. Separate SHA-256 values bind the request payload and snapshot payload. A bounded in-memory cache contains encoded immutable copies; the database is authoritative. Each request/result is limited to 64 MiB.

`ReplayController.record_analysis(identity, result, request_hash=None, archive_path=None)` records a completed, unavailable, canceled, or failed result under that original identity. Exact duplicate writes are idempotent. A different result or payload under an existing request is rejected, preserving the first observation. Repeated preparation returns a previously recorded result without scheduling new inference. The hashes and identity fields are verified when records are read or exported.

A result from an earlier state or branch remains historical. A result that finishes after a session switch is written to its original `archive_path` without replacing the active controller. The response explicitly reports whether its identity is still eligible for the current display; recording never authorizes an economic action. The GUI independently gates display by its current selection identity.

Missing-pack and input-preparation failures are recorded immediately with null probabilities, typed reasons, the observed snapshot, and the selected draft. They return `analysis_identity`, `selection_hash`, `state_version`, and `already_archived=True`; they do not dispatch an inference worker. A rejected request for an older version retains that requested version in its request context and records the actual observed version, without fabricating an old snapshot.

`export_record()['analyses']` includes pending requests and completed results from every branch of the session, retaining each original branch identifier. Restore reads these frozen records without recomputing probabilities. Initial-fill benchmarks use `prepare_analysis(..., register=False)` inside the economic transaction because their own frozen inputs are committed atomically with the campaign and benchmark ledger event.

Focused tests cover immutable deep copies, conflict rejection, duplicate retrieval, stale branches, a closed original session, pending and unavailable records, worker missing-pack failures, request/result/identity tampering, and unchanged economic state. The actual desktop spawned-analysis export check is recorded separately in `runtime/results/desktop-analysis-archive/result.json`. These are persistence checks; they do not qualify an otherwise unqualified numerical model pack.
